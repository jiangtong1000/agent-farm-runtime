# Maintenance review — 2026-10-03

## Recommendation

Upgrade this repository incrementally. Keep the task store, lease fencing,
validated transitions, recoverable state/event commits and separation between
runtime, farmkit and board. The reported operational failures do not justify
reconstructing those components.

This is a single-owner research control plane: model sessions are disposable,
external Slurm jobs survive them, and scientific decisions remain outside the
mechanical reconciler. The existing architecture fits that context. Replacing it
with a distributed service or an event-sourced database would add migration and
operational work without resolving the observed configuration, notification and
access problems directly.

The access layer needed a focused structural change: an execution epoch and an
interactive endpoint's lifetime are different things. Access schema 2 adds
immutable endpoint generations with compare-and-swap publication and explicit
process roles. Runtime task/receipt protocol 4 remains unchanged. Native OpenSSH
supplies transport; Python's logging module supplies log rotation. The smoke
worker reuses the same tick/receipt path as the integration tests.

This follows the requested [Ponytail principle](https://github.com/dietrichgebert/ponytail#how-it-works):
understand the real failure, reuse existing code and platform facilities, and
retain validation and recovery guarantees while removing unnecessary machinery.

## Validation

The final full suite passed on both Python 3.11.12 and 3.13.3: **698 passed,
2 skipped** per interpreter, with the isolated tmux and native SSH canaries
enabled. The skips are optional checks against an explicitly supplied source
snapshot and a reference deployment wrapper; no private deployment was selected.

```bash
FARM_RUN_ACCESS_TMUX_CANARY=1 FARM_RUN_TMUX_CANARY=1 FARM_RUN_SSH_CANARY=1 \
  python -m pytest -q --tb=short -rs
```

Real canaries ran on tmux 2.7 and 3.2a. Native OpenSSH 8.7 tests used disposable
loopback sshd, keys and host records for PTY, ProxyJump, reconnect and strict
host-key rejection. Their remote protocol wrapper is synthetic; separate public
CLI tests exercise real access adoption and tmux attachment. This is not a
production Slurm turnover or site-MFA certification.

The wheel built successfully; source compilation and `git diff --check` passed.
CI now includes tmux 2.7/distro canaries and Windows/macOS connection-contract
checks. That workflow is configured but has not been run on GitHub in this review.

## Deployment boundaries

Access readers must understand schema 2 before a generation pointer is published.
Legacy records remain unchanged. Use the existing stopped-writer upgrade process,
then explicitly adopt the intended endpoint; upgrading code is not an implicit
endpoint publication. See [compatibility](COMPATIBILITY.md), [operations](OPERATIONS.md),
[access](ACCESS_PROTOCOL.md) and [connection setup](CONNECT.md).

Storage probes demonstrate local operations only, not cross-node filesystem
exclusion or persistence after host failure. Role adoption verifies the selected
process identity and pane ancestry; the operator identifies its semantic role.
Doctor examines only the explicitly supplied socket inventory. Agent-host policies,
worker credentials and production farm state are unchanged by this maintenance.
Attachment is a point-in-time check. The final native tmux guard refuses a changed
endpoint and prints a diagnostic, but on tmux 2.7 that diagnostic branch can exit
zero; a zero terminal exit status is not evidence that attachment was authorized.

Continue improving at observed boundaries: keep smoke tests executable, exercise
turnover on the actual deployment, and retain crash/regression tests when cleaning
up implementation. Multi-user authorization, multi-writer orchestration and
cross-storage relocation would require a separate architecture decision; they are
not established requirements for this runtime.
